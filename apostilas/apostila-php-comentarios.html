O que são comentários?

Conceito, propósito e tipos disponíveis no PHP

Comentários são trechos de texto dentro do código-fonte que o interpretador PHP ignora completamente durante a execução. Eles existem exclusivamente para os desenvolvedores — seja para explicar a lógica de um algoritmo, marcar pontos de atenção, ou desativar temporariamente um trecho de código durante testes.

Em PHP, ao contrário de variáveis e funções, comentários não afetam o desempenho da aplicação. O interpretador os lê, identifica como comentário, e passa para a próxima instrução. Isso significa que você pode e deve usar comentários sem preocupação com impacto no tempo de resposta.

🔑 Conceito-Chave
Comentários não são executados. O PHP os descarta antes de processar qualquer instrução. Eles vivem apenas no código-fonte — nunca chegam ao navegador ou ao cliente.

Por que comentar o código?

Os três pilares da documentação inline

Há três razões principais para usar comentários, e todas giram em torno de uma ideia central: código é lido muito mais vezes do que é escrito. Um projeto PHP real pode ter dezenas de colaboradores e durar anos — o comentário de hoje economiza horas de debugação amanhã.

📖 Explicar para outros

Colegas de equipe, revisores de código e contribuidores open source precisam entender rapidamente o que cada trecho faz — sem precisar executar o código mentalmente.

🕐 Lembrar a si mesmo

Todo desenvolvedor já voltou ao próprio código meses depois e se perguntou "por que fiz assim?". Um comentário curto poupa essa reconstituição.

🔇 Desativar código

Durante testes e depuração, é comum comentar linhas para isolar comportamentos sem deletar código que pode ser necessário novamente.

📝 Documentar APIs

Com PHPDoc (/** */), os comentários alimentam ferramentas automáticas de documentação como phpDocumentor e IDEs.

3

Sintaxe básica do PHP

Estrutura de um arquivo .php antes de comentar

Antes de mergulhar nos comentários, é importante entender onde eles podem aparecer. Todo código PHP fica dentro das tags <?php e ?>. Comentários podem ser colocados em qualquer ponto dentro dessas tags — antes, depois ou no meio das instruções.

      
PHP

      
<!DOCTYPE html>
<html>
<body>

<?php
// Todo código PHP fica aqui dentro
echo 'Hello World!';
?>

</body>
</html>
⚠️ Atenção
A extensão padrão de arquivos PHP é .php. O servidor web (Apache, Nginx) precisa estar configurado para interpretar arquivos com essa extensão — caso contrário, o código PHP será enviado como texto puro ao navegador.
4

Comentário de linha única — //

A forma mais comum de comentar em PHP moderno

O comentário com // ignora tudo que vem após ele até o fim da linha. É o estilo mais usado em PHP moderno, herdado do C++ e adotado também em JavaScript, Java e outras linguagens — facilitando a transição entre tecnologias.

Pode ser usado de duas formas: antes de uma linha de código, explicando o que ela faz; ou no final da linha, como anotação inline. Para comentários longos, prefira colocá-los antes da instrução.

      
PHP

      
<?php
// Exibe mensagem de boas-vindas ao usuário
echo 'Bem-vindo!';

echo 'Olá, mundo!'; // Comentário inline no fim da linha

// Esta linha está desativada temporariamente para teste:
// echo 'Linha desativada';
?>

Boas práticas com //

  • Use para explicar o porquê de uma decisão, não apenas o o quê — o código já mostra o que faz.
  • Mantenha os comentários atualizados: um comentário desatualizado é pior do que nenhum comentário.
  • Evite o óbvio: // incrementa x antes de $x++ não agrega valor.
💡 Dica
Na maioria dos editores (VS Code, PHPStorm), o atalho Ctrl+/ (ou Cmd+/ no Mac) comenta e descomenta a linha atual automaticamente — muito útil durante depuração.
5

Comentário de linha única — #

Sintaxe alternativa herdada do Shell/Perl

O caractere # tem o mesmo comportamento de // — ignora tudo até o fim da linha. É uma herança das linguagens de script Unix (Bash, Perl, Python) e foi incluída no PHP para facilitar a migração de desenvolvedores vindas dessas tecnologias.

Na prática, # e // são intercambiáveis em PHP. A preferência da comunidade moderna (e do guia de estilo PSR-2) é pelo //, mas você encontrará # em projetos legados e scripts CLI.

      
PHP

      
<?php
# Estilo herdado do Shell — funciona igual ao //
echo 'Olá!';

echo 'Mundo!'; # Comentário inline com #
?>

Comentário multilinha — /* */

Para blocos longos de documentação e desativação de código

O bloco /* ... */ permite comentar múltiplas linhas de uma vez. Tudo entre o abridor /* e o fechador */ é ignorado pelo PHP — inclusive quebras de linha e outras marcações de comentário dentro do bloco.

É especialmente útil para: descrever o propósito de uma função antes da sua declaração, desativar um bloco extenso de código durante depuração, e escrever cabeçalhos de arquivo com informações de licença, versão e autor.

      
PHP

      
<?php
/*
  Este arquivo gerencia o cadastro de usuários.
  Autor: Maria Silva
  Versão: 2.1
  Última modificação: Setembro de 2026
*/

/* Comentário
   em várias
   linhas */
echo 'Continuação normal do código';
?>

Desativar blocos de código

Um caso de uso muito prático do /* */ é envolver um trecho inteiro de código para desativá-lo temporariamente durante testes, sem precisar deletar e re-escrever:

      
PHP

      
<?php
echo 'Esta linha é executada';

/*
echo 'Esta linha está desativada';
echo 'E esta também';
$resultado = calcularTotal($itens);
*/

echo 'Voltou a executar normalmente';
?>
⚠️ Atenção — Aninhamento
Comentários /* */ não podem ser aninhados. O PHP encontra o primeiro */ e encerra o comentário, independente de quantos /* foram abertos. Isso pode causar erros de sintaxe inesperados.
7

PHPDoc — /** */

Documentação estruturada para IDEs e geradores automáticos

O PHPDoc é uma convenção de comentário multilinha que começa com /** (duas asteriscos) em vez de apenas um. Ferramentas como phpDocumentor, IDEs (PHPStorm, VS Code com extensões) e analisadores estáticos (PHPStan) leem esses blocos para gerar documentação automática e fornecer autocomplete inteligente.

      
PHP

      
<?php
/**
 * Calcula o preço total com desconto aplicado.
 *
 * @param float $preco    Preço original do produto
 * @param float $desconto Percentual de desconto (0 a 100)
 * @return float          Preço final após desconto
 */
function calcularPreco(float $preco, float $desconto): float {
    return $preco * (1 - $desconto / 100);
}
?>

💡 Dica Profissional
Em projetos com times maiores, adote PHPDoc em todas as funções e classes públicas. Além de gerar documentação automaticamente, o PHPStorm e o VS Code usam essas anotações para oferecer autocomplete com tipos corretos — reduzindo bugs antes mesmo de executar o código.

Exercício Prático

Adicione os comentários corretos ao código

O código abaixo está funcional, mas sem documentação. Adicione os tipos de comentário indicados em cada ponto:

📋 Código sem comentários
          
PHP

          
<?php

/* ① Adicione um PHPDoc aqui */
function somar($a, $b) {
    // ② Explique por que retorna int
    return (int) ($a + $b);
}

$resultado = somar(5, 3);
echo $resultado; // ③ Adicione comentário inline
?>
✅ Solução comentada
          
PHP

          
<?php

/**
 * Soma dois números e retorna inteiro.
 * @param mixed $a Primeiro valor
 * @param mixed $b Segundo valor
 * @return int Soma truncada
 */
function somar($a, $b) {
    // Cast para int evita retorno float
    return (int) ($a + $b);
}

$resultado = somar(5, 3);
echo $resultado; // Saída: 8
?>
✅ Gabarito
① PHPDoc com @param e @return · ② Comentário // explicando o cast para int · ③ Comentário inline mostrando o valor esperado de saída

Resumo

Principais aprendizados e próximos passos

💬 3 Tipos de Comentário

// e # para linha única; /* */ para blocos; /** */ para documentação PHPDoc.

🚫 Nunca executados

O PHP ignora completamente os comentários — eles não afetam desempenho, lógica ou saída do programa.

📌 Prefira //

O estilo // é o recomendado pelo guia PSR para PHP moderno. Use # apenas em código legado ou scripts de linha de comando.

🔬 PHPDoc para APIs

Use /** */ em funções e classes públicas para habilitar autocomplete nas IDEs e geração automática de documentação.

🚀 Próximos Passos
Agora que você domina comentários PHP, explore: Variáveis e tipos de dados, funções com tipagem estrita (PHP 8+), e ferramentas de análise estática como PHPStan e Psalm que usam os comentários PHPDoc para encontrar bugs antes da execução.
